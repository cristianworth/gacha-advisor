# Meta preview

Use the game established in the chat. An explicit game, patch, or server overrides the default. With no patch specified, preview the next version after the one live on the relevant server at the time of research. Verify which version is live first, especially on launch day. Ask for the game only if it cannot be resolved, and for the server only if it changes the answer and cannot be inferred.

## Research

- Follow the [Advisor instructions](../../../advisor/gacha-game-advisor.md). Check official announcements for the version, schedule, phase assignments, banners, and reruns. An announced character or rerun can still have an unconfirmed phase or date. Use the game's own banner schedule and mark unpublished details as pending. Include server or timezone when it affects dates.
- For new characters, verify the element or equivalent and role from published information. Separate confirmed kit facts from preliminary team and meta analysis. Use beta or leaks only on request, with explicit labels. If the evidence is too thin for a rating or representative team, mark it **em aberto** and name what would resolve it.
- Read the relevant [account snapshot](../../../advisor/account-snapshots.md) and explicit newer account facts in the chat. Judge account fit by the team the character enables or improves, whom they replace, available alternatives, signature or dupe dependence, and competing pulls or budget when known.

## Response

Keep it short and in Portuguese.

1. **Próxima versão.** Give the patch number and confirmed launch date, then a compact table of phases, dates, debuts, and reruns. Mark missing details in place. Link the official schedule or announcement.
2. **Personagens novos.** Give one compact entry per debut: **elemento/função · meta · time de referência · veredito para a conta**. Use **must-pull** for a broadly high-impact pick with strong evidence, **bom** for strong value in the intended teams, **okay** for a niche or sidegrade, and **ruim** for weak value in the intended role. Mark pre-release judgments as preliminary. Give one representative team when supported and label it as provisional when appropriate. If it uses unowned or unconfirmed teammates, identify the relevant gap and give an owned substitute only when it changes the pull decision. Give a separate **PULL / SKIP / WAIT / DEPENDE** verdict with one account-specific reason. For **WAIT** or **DEPENDE**, say what would change the decision.
3. **Prioridade de pulls**, when choices compete. Give the top priority in one line. Assess a rerun's pull value when asked or when it materially changes that priority.

Cite evidence for kit or meta claims. Use a short role or synergy explanation when it affects the verdict. Leave full builds, rotations, and detailed banner math for a follow-up.
